# Gary Agency CMS implementation and rollout

Local implementation prepared 13 November 2026. The CMS database migration was authorized and applied on 16 November 2026 (hosted version `20261116043114`). Website deployment and CMS staff-role bootstrap have not been performed.

## Scope

The existing staff portal now includes **Content management** at `portal.html?area=staff&view=cms`. It mounts the pinned, application-local shared CMS foundation; it does not connect to a universal administrator or another site's database adapter.

Seven collections manage bilingual services, eligibility information, document requirements, process steps, FAQs, articles/guides, and landing sections. Core fields include EN/VI title, summary, body and SEO overrides. Collection fields include service relationships, official source links, review dates, ordering, service groups, and public image URLs.

The editor supports drafts, review submission, publishing, archiving, revisions and restoring older content as a new draft. Version checks reject concurrent overwrites. A saved edit to an already published entry retains the old public snapshot until the revised entry is reviewed and published. Restoring a revision does not publish it automatically.

The public website reads only published snapshots. Services, service eligibility/document details, process steps, FAQs, guides and landing copy are rendered from these records with safe text nodes. EN/VI changes re-render published copy. Source content remains available as an outage/unprovisioned fallback; failed loads never imply successful writes.

The migration includes 19 source snapshots of the existing four services, four process steps, five FAQs and six landing sections. It adds no new eligibility or immigration-law claims. Those collections and guides can be authored/reviewed by staff.

## Independent authorization

- `gary_private.cms_members` has `editor`, `publisher`, and `admin` roles plus an active flag.
- Every CMS member must independently remain an Agency staff member in `gary_private.staff_members`. A Home role, Jobs role, or editable Auth metadata cannot grant access.
- Editors can save drafts, request review, inspect revisions and upload editorial media.
- Publishers/admins can publish reviewed content or archive it. The server rejects direct draft publication.
- No browser-facing membership-management grant is provided. Owner-reviewed SQL bootstraps/revokes CMS roles.
- Private customer case documents stay in `gary-documents`; the CMS does not alter case access or workflow.

## Tables and RPCs

- Working records: `public.gary_cms_entries`
- Immutable revision snapshots: `public.gary_cms_revisions`
- Public published snapshots: `public.gary_cms_public`
- Editorial-media registry: `public.gary_cms_media`
- Membership: `gary_private.cms_members`
- RPCs: `gary_cms_capabilities`, `gary_cms_save`, `gary_cms_transition`, `gary_cms_restore`, `gary_cms_register_media`

Writes use checked RPCs, not unrestricted client updates. All application tables have RLS. Public snapshot rows omit actor identities. Conflict failures use SQLSTATE `40001`; access failures `42501`; missing bilingual content/review/invalid fields `23514`. The UI translates these conditions and does not present raw database errors.

## Editorial media

`gary-cms-media` is a **public editorial-image** bucket: JPEG/PNG/WebP/AVIF up to 5 MiB. Do not upload private case documents to it. SVG, HTML and PDF are not accepted. Upload paths belong to the current user and use random filenames. Supabase policies additionally guard this bucket against permissive policies belonging to another application.

Alternative text is stored in both languages and copied into published image metadata. The public site permits images from its own origin and the configured Supabase origin. Publication accepts local absolute asset paths or this application's public media bucket, avoiding image URLs that CSP would block.

Deletion/replacement is deliberately unavailable until usage/lifecycle tracking is defined; this prevents removing an image still referenced by a publication. A successful upload with failed metadata registration can leave an orphan editorial object for owner reconciliation. No automatic destructive cleanup runs.

## Applications and News & Guides Trash

Review and apply the Visa Trash lifecycle migration before releasing the portal. Operations Admins manage application Trash. CMS Admins manage News & Guides Trash. Restoring an application retains its workflow status. Restoring an article creates a draft and requires a separate publication action.

Set the approved minimum days from the Trash date in `gary_private.trash_retention` for `case` and `article`. Keep any applicable record holds in `gary_private.trash_holds`. Permanent deletion is unavailable for a kind until its retention rule is configured. Staff can restore records while retention or holds prevent permanent deletion.

Case cleanup uses the Storage API for the prepared keys in `gary-documents`. Once cleanup starts, finish it from Trash. A partial or unconfirmed cleanup keeps the row available for retry and locks Restore to protect document references. CMS library images use their separate media lifecycle. Permanent deletion keeps only the operational deletion audit fields, including the record identifier, action, acting staff identifier and timestamp.

## Local verification

```sh
npm run check
npm test
npm run test:cms
npm run build
```

CMS tests use JSDOM, mock clients and in-memory PGlite. They do not contact or migrate the hosted project. They cover cross-app/customer denial, editor/publisher boundaries, direct draft publication denial, working/public snapshot isolation, revision restore, stale writes, media policies, bilingual rendering, pagination, safe text rendering, and unavailable-backend states.

## Remaining rollout and product limits

- Hosted schema, roles, media upload and browser behavior must be verified after authorized provisioning/deployment; local tests are not production verification.
- The current static architecture renders CMS content after a public snapshot request. Guides are displayed on the landing page and can be linked with `?article=<slug>#cms-articles`; dedicated server-rendered/indexable article routes are a separate SEO extension.
- Working drafts/review/public snapshots are protected, but a multi-author review policy requiring a different reviewer from the author is not implemented.
- Structured visa cases, deadlines, private document review and billing remain outside this CMS increment, as requested.
- The application retains independent Agency staff/Auth lifecycle behavior. This change does not resolve the pre-existing global credential-administration issue in the shared Auth project.
